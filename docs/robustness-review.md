# biliSum 健壮性与安全复查记录

以下保留 0.1.6 的复查结果，并按版本追加后续修复、生产构建、自动化测试和依赖审计记录。这里记录实际覆盖范围；测试通过不等于软件不存在任何缺陷。

## 已修复的问题

| 范围            | 原问题与触发条件                                                           | 修复后的行为                                                                                     |
| --------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 字幕切换 / 刷新 | 请求开始先清空字幕和结果；新请求失败后无法继续使用旧内容                   | 同一视频保留旧内容，成功后才替换；语言切换失败回退选择，显示重试提示                             |
| 总结中断        | 网络断开、长度限制或手动停止后丢失已收到的正文                             | 保留未完成草稿，允许复制和下载，预览与文件均注明不完整；不覆盖完整缓存                           |
| 分 P 标识       | 备用数据没有 pages 时可能把根 CID 当作当前分集 CID                         | 非第一 P 必须找到匹配分集；拒绝缺少 BV 标识、非安全整数或错误视频身份的数据                      |
| 字幕列表        | 一条坏地址或 null 条目破坏整组语言；重复 ID 破坏界面列表                   | 逐项校验，过滤坏项和重复 ID，保留有效语言；真实接口错误不会被空列表掩盖                          |
| JSON 响应       | null、数组、HTML 错误页导致内部异常；响应没有大小上限                      | 在解析前限制读取字节，验证顶层对象，提供可操作的中文提示；中断或超时取消读取                     |
| 模型事件流      | 未限制单个事件；只有 JSON 响应时可绕过正文长度限制；部分换行不兼容         | 限制事件与总流量，统一正文上限；支持 CR、LF、CRLF 和 BOM；结束标记到达后关闭读取                 |
| 取消请求        | 取消权限等待后仍可能进入请求函数；浏览器注入可能长时间占用加载状态         | 发送前检查取消状态，测试可取消；页面备用数据读取最多等待 4 秒，超时回到 API 流程                 |
| 设置状态        | 初次设置未加载完成时可打开空白表单并覆盖旧设置；测试成功提示可能对应旧输入 | 加载完成前禁用设置入口；输入改变清除旧提示；保存期间防止关闭，取消 / 关闭测试不发起延迟请求      |
| 字幕导入        | JSON body 非数组时报 TypeError；损坏 SRT/VTT 被当作 TXT；时间格式过宽      | 校验结构与分钟、秒范围；坏时间轴明确报错；TXT 中的箭头保留为文本；坏文件不清空原字幕             |
| 缓存匹配        | 只比较格式化到整秒的文本，忽略来源和结束时间                               | 使用 SHA-256 比较来源、完整时间轴和正文；不自动恢复旧格式缓存                                    |
| 缓存写入        | 多侧栏的读改写可能互相覆盖；一条损坏缓存干扰其他结果                       | 使用扩展源的 Web Locks 串行写入；按本次生成格式合并；逐记录校验，坏导图不影响好总结              |
| 缓存空间 / 故障 | 写满后生成成功但结果不能保存                                               | 限制为 12 条与约 6 MB 的 JSON 预算；配额错误逐步淘汰旧记录；其他错误显示下载提示，后续写入可恢复 |
| 预览隐私        | 原 HTML 允许范围偏宽，未明确禁用链接 ping 等联网属性                       | 使用排版标签和属性允许列表；禁用外部资源、脚本、框架与 ping；链接添加 noopener noreferrer        |
| 网络边界        | 已校验的字幕 URL 仍可能重定向，且下载字幕携带不必要的 Cookie               | 字幕下载省略 Cookie 并拒绝重定向；B 站元数据接口仍携带登录状态；AI 请求不携带 Cookie             |
| 错误信息        | fetch 抛出的消息可能包含密钥，复制权限错误较晦涩                           | 对模型请求错误做密钥脱敏，取消、超时、网络和剪贴板失败使用明确提示                               |
| 文件导出        | Windows 保留设备名 / 截断后的尾点可能产生非法文件名，PNG 加载无超时        | 修正设备名与尾点，统一对象 URL 清理，PNG 图像加载超时提供 SVG 替代提示                           |
| 交互            | 字幕来源改变后保留旧搜索词，造成新字幕看似为空；长字幕费用不明显           | 来源更新时重置搜索；生成前显示分段数量与多次请求提示；显式点击重试，不自动重发付费请求           |

| 样式一致   | 页面下拉框、密钥和搜索输入分别定义外观         | 共用字体、圆角、边框、焦点与箭头；常规 36px / 紧凑 32px，深浅主题和窄屏一致                    |

| AI 速率    | 多个侧栏与连接测试相互独立，429 后可连续点击   | 同源 Web Locks 串行、3 秒起始间隔、session 共享冷却、Retry-After 秒 / 日期解析，无自动付费重试 |

| 视频切换   | 导航 180ms 防抖期间旧准备任务可能继续发出      | 切换事件立即中止任务、清理旧状态，仅读取资料防抖；异步标识完成后再次核对任务身份               |
| 结果保存   | 等待字幕摘要标识期间可能读取新页面的结果       | 提前计算字幕标识并复核 serial，保存前同步捕捉结果快照，避免旧视频混入新结果                    |
| 连接测试   | 取消授权等待后界面仍被占用，旧进度与错误并存   | 可立即取消等待并恢复操作；迟到授权不补发请求；失败时清除旧进度                                 |
| Unicode    | 超长字幕切分可能截断 emoji 的代理对            | 分段边界保留完整 Unicode 代理对，保证内容完整与预算不越界                                      |
| 封面地址   | 正则可能被查询参数中的伪 CDN 后缀绕过          | 使用 URL 的实际 hostname 检查 HTTPS CDN 与凭据 / 端口，加载失败回退视频图标                    |
| API Key    | 中文、隐藏字符、内部空格可造成 Headers 错误    | 保存或权限申请前校验可见 ASCII，明确提示无效字符；错误继续脱敏                                 |

## 0.1.4 流式调用与超时修复

| 范围       | 原问题与触发条件                                              | 修复后的行为                                                                                                                  |
| ---------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 接收方式   | 导图、字幕笔记和合并笔记等待整包响应，无法及时接收服务输出    | 生成请求统一设为流式，同时接受 JSON 响应；笔记和导图静默积累完整正文，校验后才使用；连接测试仍为非流式                        |
| 事件完整性 | EOF 会封口尚未完成的 SSE 事件，可能把截断的完成标记误当成成功 | 仅接受空行封口的事件；尾部不完整事件丢弃；缺少明确结束标记、正文被长度上限截断或异常结束时失败，不缓存                        |
| 超时判断   | 固定 180 秒也会中止仍持续输出的生成                           | 等待响应 180 秒、响应后停滞 90 秒、整次请求总上限 10 分钟；字节心跳与思考可刷新停滞计时，总时限不可延长；取消和结束释放计时器 |
| 进度与性能 | 只有笼统等待提示，空片段或思考片段重复触发正文回调            | 区分等待响应、已连接、思考、接收正文与校验；仅新正文触发预览，阶段变化才更新提示；思考不进入结果或缓存                        |
| HTTP 错误  | 524 使用通用繁忙提示，错误正文停滞时继续等待                  | 408 / 504 / 524 提示未完整送达、可能计费与手动重试；HTML 错误页立即取消，可选 JSON 错误正文限 5 秒 / 32 KB；错误信息脱敏      |
| 资源释放   | 收到限流后保存冷却失败，尚未开始读取的响应流可能保留          | 所有完成或失败出口释放计时器，并取消未加锁的响应流；存储故障不产生自动请求                                                    |
| 结束原因   | 工具调用等异常结束原因也可能返回貌似完整的正文                | 校验候选正文与结束标记形状，拒绝工具调用、过滤、长度限制及未知异常结束；服务只发送思考而无正文时明确失败                      |
| 费用与恢复 | 请求失败后重复发送会增加计费风险                              | 无自动非流式回退或付费重试；保持同源串行、3 秒实际起始间隔和限流冷却；成功笔记可复用，断流片段不可复用                        |

协议复核参考 WHATWG 的 SSE 空行封口规则和 OpenAI Chat Completions 的 delta / finish_reason 文档。所有验证使用本地模拟服务；未调用用户的模型服务或使用实际密钥。流式传输是否及时转发仍取决于服务，不能承诺解决所有 524。

## 0.1.5 Markdown 表格修复

截图中的表格过小由全局 CSS 造成：`display: block` 与 `width: max-content` 让表格按内容收缩，12px 字号小于正文，同时未设置单元格内边距与边框。本次恢复原生表格布局和 100% 可用宽度，字号继承 13px 正文，行高 1.7，单元格内边距为 10px × 12px。

表头加粗，隔行使用主题底色，完整行列网格使用主题边框颜色。每列保留最低可读宽度，多列表格在专用容器内横向滚动，容器可聚焦并使用左右方向键。保留 Markdown 的左 / 中 / 右对齐与安全 HTML 合并行列。

滚动容器在 HTML 清理后由脚本创建，没有放宽模型输出的样式、事件或 class 允许范围。预览包装不写入原始 Markdown，复制与下载继续保留完整源内容；已有完整缓存重新打开即应用新样式，无需重新请求模型。

新增两项浏览器回归，覆盖七层三列表格在 280 / 320 / 380 / 720px 与深浅主题下的实际字号、行列边框、内边距和宽度，以及多列长文本 / 合并行列的独立滚动、方向键、对齐、安全清理、源码切换和实际下载。生产构建截图记录于 `docs/markdown-table-*-preview.png`。720px 窗口内表格与内容区域同为 650px；380px 同为 310px；280px 内容区域 218px，表格 274px，在内部滚动。均无页面横向溢出或浏览器未处理异常。

## 升级与仍需了解的限制

1. 使用 `dist` 安装目录或 `biliSum-0.1.6-chrome.zip`。已安装版本在扩展管理页刷新后，关闭并重新打开侧栏。
2. API 设置保留，0.1.3 / 0.1.4 / 0.1.5 的完整结果缓存可继续读取。0.1.2 及更早版本的缓存身份算法不同，不会自动恢复；升级前请导出重要结果。完整结果的缓存也是有限历史，不替代用户备份。
3. 未完成草稿只保存在当前侧栏会话内；关闭侧栏、切换视频或更换字幕前请复制或下载。导图是结构化 JSON，不展示或导出无效的半成品树。
4. API Key 在本地扩展存储中以普通字符串保存；受浏览器扩展隔离保护，但不是针对本机恶意软件的加密保险库。模型服务能读取用户发送的字幕与视频元数据。
5. 请求取消阻止本地继续等待和后续请求，不保证服务端停止处理或撤销费用。长字幕失败后可复用当前侧栏内成功的笔记，闲置 30 分钟过期；最多 4 个输入、约 200 万字符，关闭侧栏或缓存淘汰后需重新分析。中断的片段不缓存，每次最终生成仍可能计费。
6. 真实 B 站登录、风控、字幕地址变化、Chrome 原生授权弹窗、模型兼容性及服务商计费，本轮没有使用真实账户实测。接口失败会给出刷新、切换语言、检查配置或导入字幕的路径。
7. 模型输出仍可能不准确，提示注入无法仅靠提示词完全消除；本扩展不会执行模型命令，预览输出受 HTML 允许列表限制，事实仍应结合原视频核对。
8. 源码使用 Git 管理，主分支为 `main`，远端为 `LcodeCoder/biliSum`。依赖、`dist`、`.output` 与安装 ZIP 不纳入源码提交；从源码安装请先执行 `npm ci` 与 `npm run build`。
9. 速率政策以 API 源为单位，同源不同账户与模型共用保守队列。浏览器或扩展重启后 session 冷却数据会清空，仍需遵循服务商限制；没有把 3 秒间隔作为各服务商的额度保证。
10. 分布图由导图结构计数，不能代表原视频篇幅、重要性或模型准确性；PNG 全图受最大 4096px 导出边长限制，复杂导图可下载 SVG 或 Markdown 大纲阅读。

本轮设计核对了 Chrome 的 storage API 和 Web Locks API 文档；session 用于跨侧栏共享节流状态，临时笔记只留在侧栏内存。
